# 分阶段交付路线

每个阶段都必须形成可独立运行、可验收的版本。上一阶段通过后再扩大范围；功能排序和范围取舍遵循[拾页产品设计原则](product-principles.md)。

## 阶段一：单用户核心服务（已完成）

目标：建立可信的数据与身份基础，并跑通手动保存和找回。

- [x] Go 单进程应用与内嵌 Web UI
- [x] SQLite 单文件存储与自动建表
- [x] Passkey-only 初始化和登录
- [x] 一次性初始化链接与 CLI 恢复链接
- [x] 服务端 WebAuthn ceremony 和应用会话
- [x] 手动新增、URL 规范化、去重
- [x] 标题、网址、备注基础检索
- [x] 稍后阅读、收藏、编辑和删除
- [x] 安全响应头、Origin 检查和最小化 Cookie 权限
- [x] Dockerfile 与 Compose 基础

验收：测试、静态检查和二进制构建通过；本地服务健康检查、初始化状态、WebAuthn 注册起始、书签新增、去重和中文基础查询通过。

## 阶段二：Chromium 收集与轻量归档（已完成）

目标：把“手动粘贴链接”升级为“一键保存”，并在低配 VPS 上可靠保存正文。

- [x] Manifest V3 Chromium 扩展
- [x] `activeTab` 临时页面权限
- [x] 工具栏、快捷键和右键菜单保存
- [x] 扩展设备配对与 capture-only Token
- [x] 幂等 Capture API
- [x] SQLite 持久化后台任务队列
- [x] 限并发、限时、限大小的 HTTP 抓取
- [x] 正文提取、清理和压缩 Blob 存储
- [x] 登录页/SPA 的显式浏览器端正文提交
- [x] 归档失败可见、可重试且不影响 URL 保存

验收：在 Chrome 中一键保存公开网页，接口立即响应，后台归档完成；抓取失败仍保留书签；扩展无持续全站访问权限。

## 阶段三：中文找回与数据可靠性（已完成）

目标：让数万条中文书签仍然容易找回，并保证可以离开或恢复系统。

- [x] SQLite FTS5 索引
- [x] 中文二元词与中英文混合查询
- [x] 标题、标签、备注和正文分字段加权
- [x] 命中片段与无结果反馈
- [x] 标签编辑
- [x] HTML、JSON、CSV 导出
- [x] 数据目录备份与恢复校验
- [x] 存储用量与归档状态面板
- [x] Docker 部署、升级和迁移文档

验收：真实中文查询集通过；JSON、CSV 和 HTML 导出内容完整；备份包含数据库与归档 Blob，解包恢复后书签数量、内容哈希和 Blob 内容一致。

## 阶段四：迁移与批量整理（已完成）

目标：让已有书签可以低风险迁入，并能在一次操作中整理大量数据。

- [x] 拾页 JSON 导入
- [x] Netscape 浏览器书签 HTML 导入
- [x] CSV 自动识别与字段映射
- [x] UTF-8 与 GB18030 中文文件编码
- [x] 导入前格式、数量和样本预览
- [x] URL 规范化、无效数据跳过与重复合并
- [x] 10 MB / 20,000 条资源上限
- [x] 导入默认不抓取正文，可显式开启后台归档
- [x] 书签多选与当前页全选
- [x] 批量添加/移除标签
- [x] 批量修改稍后阅读与收藏状态
- [x] 批量删除与二次确认

验收：三种导入格式及 CSV 自定义映射测试通过；重复 URL 不产生副本；默认导入不会制造大规模归档队列；批量更新和删除在单个事务中完成；桌面端导入与多选界面通过浏览器验收。
